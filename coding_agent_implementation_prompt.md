# Implementation Specification: Outbound Vision Backend API (`POST/GET /api/v1/scan`) + Active Learning Collector

## 1. Objective & Context

You are tasked with refactoring and rebuilding the outbound vision codebase into a **clonable, Dockerized, production-ready FastAPI backend service** managed exclusively with **`uv`**.

You have access to the existing repository files (`agent.py`, `segmentor.py`, `scanner.py`, `code_reader.py`, `schemas.py`, `segmentation_api.py`, `hosting-grounding-dino (1).ipynb`) and the architectural research document (`BRAINSTORM.md`). Treat the existing Python files as a behavioral reference to extract proven domain logic from, **not** as a structural template.

### Core Architectural Requirements

1. **Strict `uv`-Only Toolchain (Zero `pip`):**

   * Manage all dependencies, virtual environments, lockfiles, and command executions exclusively with **`uv`** (`pyproject.toml` + `uv.lock`).

   * **Never** use `pip install`, `python -m pip`, or `requirements.txt` anywhere in the codebase. Use `uv sync`, `uv add`, and `uv run` exclusively.

2. **Backend-Only FastAPI Service (`/api/v1/scan`):**

   * The service is strictly a backend API—it does **not** manage hardware cameras or serial triggers directly. Any client (currently a local device with a 12MP Logitech webcam triggered by a person, and later an ESP32-triggered capture client) simply sends an image to `/api/v1/scan` and receives all decoded barcodes in the response.

   * Strip out the external `agent_runtime`, `agent_platform`, `BaseTool` registry, tenant/connector factories, event bus, and internal HTTP/base64 round-trips between stages. Once the image is received at `/api/v1/scan`, keep the full frame and crops as in-memory `numpy.ndarray` objects end-to-end.

3. **Mandatory Pipeline Execution Order:**
   Every request to `/api/v1/scan` **must** execute in this exact sequence:
   

   $$
   \text{Receive Image (API)} \longrightarrow \text{Segment (Grounding DINO)} \longrightarrow \begin{cases} \text{Parallel Code-Reader (pyzbar / zxing-cpp)} \longrightarrow \text{API Response} \\ \text{Async Dataset Collector Queue (Background Process)} \end{cases}
   $$

4. **Boolean Feature Flags via `.env`:**
   Keep the previously proposed OCR (`ENABLE_OCR`) and VLM Agent Enrichment (`ENABLE_AGENT`) integrations in the pipeline right after the Code-Reader stage, gated by boolean environment variables (both defaulting to `false`). When `false`, do not load OCR weights into VRAM and do not execute those stages.

5. **Automatic Background Dataset Collection (`ENABLE_DATA_COLLECTION=true`):**
   Spawn a dedicated background `multiprocessing.Process` at FastAPI startup. As soon as the segmentor produces padded crops during a `/api/v1/scan` request, automatically push the raw frame and all segments non-blockingly to the background process. This worker uses the **Gemma API in batch mode** to visually verify every segment (`image 1: true/false`, etc., outputting 1 token per crop) and stores the image and verified annotations to disk for training a lightweight detector after one week of use.

6. **Turnkey Docker Experience:**
   Provide a `Dockerfile`, `docker-compose.yml`, `pyproject.toml`, `uv.lock`, `.env.example`, and `Makefile` so the repository can be cloned and run immediately with a single command (`make up`).

## 3. Detailed Component Specifications

### 3.1. FastAPI Ingestion Endpoint (`src/main.py` & `src/utils/image_io.py`)

* **Endpoint Routing (`/api/v1/scan`):**

  * Expose `/api/v1/scan` supporting both `POST /api/v1/scan` and `GET /api/v1/scan` (route both HTTP methods to the same scan handler so whether a client sends a `POST` multipart upload, a JSON body with base64 image data, or a `GET` request with an image payload/query, it enters the pipeline seamlessly).

  * Accept either:

    1. `multipart/form-data` with an uploaded image file (`file: UploadFile = File(...)`), or

    2. `application/json` with `{"image_base64": "..."}` (and optional per-request override parameters like `prompt` or `padding`).

* **Image Decoding & EXIF Normalization (`image_io.py`):**

  * Port the EXIF orientation normalization logic from `segmentor.py` so high-resolution 12MP images with orientation tags are decoded into a standard upright `np.ndarray` (BGR) in memory once at the ingestion boundary.

* **FastAPI Lifespan Management:**

  * Use FastAPI's `lifespan` context manager to:

    1. Load and warm up Grounding DINO on the GPU once at startup.

    2. Conditionally initialize the OCR engine if `settings.ENABLE_OCR` is `True`.

    3. Initialize the persistent `ThreadPoolExecutor` for the parallel `code_reader`.

    4. Start the background `DatasetWorkerProcess` and `multiprocessing.Queue` if `settings.ENABLE_DATA_COLLECTION` is `True`, and gracefully drain/terminate it on shutdown.

* **Response Payload (`ScanResponse` in `schemas.py`):**

  * Return a clean JSON response containing:

    * `request_id`: UUID for tracing and matching against saved dataset files.

    * `barcodes`: Flat, deduplicated list of all decoded barcodes across all segments (`symbology`, `value`, `bbox_global`, `segment_index`).

    * `segments`: List of detected segments (`segment_index`, `score`, `raw_bbox`, `padded_bbox`, `barcodes`, plus optional `ocr_result` and `agent_result` when those flags are enabled).

    * `timing_ms`: Stage-by-stage latency breakdown (`decode_image_ms`, `segment_ms`, `code_reader_ms`, `enrich_ms`, `total_ms`).

    * `dataset_queued`: Boolean indicating whether the sample was dispatched to the background dataset collector.

### 3.2. In-Process Segmentor & Outer-Box Suppression (`src/segment/`)

* **In-Process Grounding DINO (`grounding_dino.py`):**

  * Port the model initialization and inference logic directly from `hosting-grounding-dino (1).ipynb` and `segmentor.py` so the model runs in-process on the GPU (`cuda` if available, else `cpu`). Eliminate `segmentation_api.py`'s HTTP hop.

  * Default text prompt: `SEGMENT_PROMPT="barcode"` (configurable in `.env`). Automatically normalize the prompt to Grounding DINO's required format (lowercase, trailing period: `"barcode."`).

* **Ignore Outer Bounding Boxes (`postprocess.py`):**

  * Grounding DINO often outputs both a larger outer bounding box (e.g., around the entire barcode block + text) and a tighter inner bounding box around the barcode bars.

  * Implement **Outer-Box Containment Suppression**:
    Given detected bounding boxes $\mathcal{B} = \{B_1, B_2, \dots, B_k\}$, for every pair $(B_i, B_j)$ where $\text{Area}(B_i) > \text{Area}(B_j)$:
    

    $$
    \text{Containment}(B_i, B_j) = \frac{\text{Area}(B_i \cap B_j)}{\text{Area}(B_j)}
    $$

    
    If $\text{Containment}(B_i, B_j) \ge \tau_{\text{contain}}$ (default `CONTAINMENT_THRESHOLD=0.80`), **discard the outer box** $B_i$ and retain the inner box $B_j$.

  * Follow containment suppression with standard class-agnostic IoU Non-Maximum Suppression (`NMS_IOU_THRESHOLD=0.50`) to remove near-identical duplicate boxes.

* **Generous Padding (Replaces CV2 Zoom):**

  * Because `"barcode"` segments tightly around the dark bars and clips the mandatory white quiet zone, apply generous configurable padding around each surviving inner bounding box:
    

    $$
    \text{pad}_x = (x_2 - x_1) \times p_x, \quad \text{pad}_y = (y_2 - y_1) \times p_y
    $$

  * Default to `SEGMENT_PAD_X=0.25` (25% horizontal padding for 1D quiet zones) and `SEGMENT_PAD_Y=0.20` (20% vertical padding), clamped to `[0, width]` and `[0, height]`.

  * Store both the **raw unpadded box** $(x_1, y_1, x_2, y_2)$ and the **padded crop box** $(px_1, py_1, px_2, py_2)$ along with the sliced `np.ndarray` crop on each `Segment` object.

### 3.3. Parallel Code-Reader (`src/decode/code_reader.py`)

* Port the decoding logic from `code_reader.py` and `scanner.py` with the following modifications:

  * **Remove the 2x `cv2.INTER_CUBIC` upscale retry.** Because the segmentor directly targets `"barcode"` on a 12MP image with 20–25% padding, synthetic upscaling does not make the bars clearer and wastes CPU time.

  * **Preserve Engine Order:** Run `pyzbar` first on the padded crop. Only if `pyzbar` returns zero results on that crop, run `zxing-cpp` as the fallback (covering DataMatrix, PDF417, and dense QR codes).

  * **Parallel Execution across All Segments:** Submit all padded segment crops from the image in parallel to the persistent `ThreadPoolExecutor(max_workers=settings.SCANNER_THREADS)` (both `pyzbar` and `zxing-cpp` release Python's GIL).

  * Ensure each crop slice passed to `pyzbar` is C-contiguous (`np.ascontiguousarray`), isolate exceptions per crop so one bad crop never fails the request, map barcode coordinates back to global image coordinates, and deduplicate the combined barcode output list by `(symbology, value)` in case adjacent padded crops overlap.

### 3.4. Background Data Collection & Batched Gemma Verification (`src/dataset_worker/`)

This subsystem runs in its own OS process alongside the main FastAPI process to build a clean YOLO training dataset over 1 week without adding latency to `/api/v1/scan`.

* **Non-Blocking Dispatch (`worker.py`):**

  * When `ENABLE_DATA_COLLECTION=true`, as soon as `/api/v1/scan` finishes segmentation and attaches the parallel `code_reader` results to the segments, enqueue a `DatasetJob(request_id, timestamp, full_frame_bgr, segments_payload)` into the `multiprocessing.Queue` via `put_nowait()`.

  * If the queue is full, log a warning and drop the sample—never block the `/api/v1/scan` HTTP response.

* **Batched Gemma Verification (`gemma_verifier.py`):**

  * The background worker pulls `DatasetJob` items and verifies every padded segment crop using the Gemma API (`GEMMA_API_BASE_URL`, `GEMMA_API_KEY`, `GEMMA_MODEL_NAME`).

  * **Batch Processing (`GEMMA_BATCH_MODE=multi_image`, default):**

    * Send all $K$ padded segment crops from the image (up to `GEMMA_MAX_BATCH_SIZE=8` per call) in a **single batched multi-image chat completion request** with each crop labeled `image 1`, `image 2`, ..., `image K`.

    * Prompt Gemma strictly for binary barcode verification:

      > *"You are a binary barcode segmentation verifier. You are given N cropped images labeled image 1 through image N. For each crop, determine whether it contains a real 1D barcode, QR code, DataMatrix, or 2D machine-readable code (even if blurry, angled, or low contrast). Respond ONLY with one line per image in the exact format `image 1: true` or `image 1: false`. Output no other words, punctuation, or explanation."*

    * Set `temperature=0.0` and `max_tokens = 8 * K`.

  * **Concurrent Single-Token Batch Mode (`GEMMA_BATCH_MODE=single_token_concurrent`):**

    * Also support firing all $K$ crops concurrently via `asyncio.gather` where each request sends 1 crop, sets `temperature=0.0` and `max_tokens=2`, and prompts Gemma to output strictly a 1-token boolean: `true` or `false`.

* **Dataset Storage Format (`storage.py`):**

  * Save to `DATASET_DIR` (`./dataset`):

    * `dataset/images/{request_id}.jpg` — the full-frame image.

    * `dataset/labels/{request_id}.txt` — YOLO normalized format (`0 <x_center> <y_center> <width> <height>`) including **every segment where `gemma_verified == True OR scanner_decoded == True`**. Combining deterministic scanner success with Gemma's visual verification ensures that blurry/glare-affected barcodes that failed `pyzbar`/`zxing-cpp` are still positively labeled in the training set rather than treated as background false negatives.

    * `dataset/crops/positive/` and `dataset/crops/negative/` — save the individual padded segment crops (`{request_id}_seg{idx}.jpg`) sorted by final verification status for easy human inspection.

    * `dataset/metadata/{request_id}.json` — full record containing image dimensions, raw and padded bounding boxes, pixel sizes, Grounding DINO confidence, `scanner_decoded` flag, decoded payloads, and `gemma_verified` boolean.

### 3.5. Scalable OCR & VLM Agent Flags (`src/enrich/`)

Keep all originally proposed integrations wired into the pipeline behind boolean `.env` flags so they can be toggled on at any time:

* **`ENABLE_OCR=false` (default):**

  * In `src/enrich/ocr_engine.py`, wrap `PaddleOCR` / `RapidOCR`. Only import and load weights into memory if `settings.ENABLE_OCR is True`.

  * When `True`, run OCR on the segments right after the `code_reader` stage and include the extracted text in the `/api/v1/scan` response.

* **`ENABLE_AGENT=false` (default):**

  * In `src/enrich/vlm_agent.py`, preserve the full structured extraction prompt, confidence bands (`0.90-1.0`, `0.70-0.89`, etc.), closed sticker-type vocabulary (`shipping_label`, `product_label`, `handling`, `warning`, `other`, `unknown`), and mechanical `needs_verification` rule from `agent.py`.

  * When `True`, execute this enrichment stage and populate `agent_result` on each segment in the `/api/v1/scan` response.

   * Configure `[[tool.uv.index]]` in `pyproject.toml` to pull CUDA 12.8 wheels for PyTorch (`https://download.pytorch.org/whl/cu128`, `explicit = true`) on Linux x86_64 so RTX 5070 (`sm_120`) support is guaranteed out of the box.

   * Generate and commit `uv.lock`.

2. **`Dockerfile` (Strictly `uv`, Zero `pip`):**

   * Base image: `nvidia/cuda:12.8.0-cudnn-runtime-ubuntu22.04` (or `ubuntu:24.04` with CUDA 12.8 runtime).

   * Copy the `uv` binaries directly from the official Astral image:
     ```dockerfile
     COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/
     ```

     ```dockerfile
     ENV UV_COMPILE_BYTECODE=1 \
         UV_LINK_MODE=copy \
         UV_PYTHON_DOWNLOADS=automatic \

     ```

   * Install required system packages via `apt-get`: `libzbar0`, `libgl1`, `libglib2.0-0`, `curl`, `git`, `ca-certificates`.

   * Copy `pyproject.toml` and `uv.lock` first, and install dependencies using `uv sync --frozen --no-install-project --no-dev` for Docker layer caching, then copy the project source and run `uv sync --frozen --no-dev`.

   * Pre-download the default `IDEA-Research/grounding-dino-tiny` processor and model weights during `docker build` using `uv run python -c "..."` so the container starts immediately without downloading weights at runtime.

   * Start the server via `CMD ["uv", "run", "--no-sync", "uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]`.

3. **`docker-compose.yml`:**

   * Configure NVIDIA GPU passthrough (`deploy.resources.reservations.devices` with `capabilities: [gpu]`).

   * Mount `./dataset:/app/dataset` and `.env:/app/.env`.

   * Expose port `8000:8000`.

   * Set `shm_size: '2gb'` (or `ipc: host`) so Python's `multiprocessing.Queue` can transfer 12MP numpy arrays between the FastAPI worker process and the `DatasetWorkerProcess` without crashing on Docker's default 64MB `/dev/shm` limit.

4. **`Makefile`:**

   * `make setup`: copies `.env.example` to `.env` if not present and creates `./dataset`.

   * `make sync`: runs `uv sync` for local development.

   * `make build`: builds the Docker image via `docker compose build`.

   * `make up`: starts the service via `docker compose up -d`.

   * `make scan IMG=path/to/image.jpg`: sends a test image to `http://localhost:8000/api/v1/scan` via `curl -F "file=@$(IMG)"` and pretty-prints the returned JSON barcodes and latency breakdown.

   * `make logs`: tails container logs (`docker compose logs -f`).
